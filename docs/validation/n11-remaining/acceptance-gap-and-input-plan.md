## Planned source C1: open two-face plate

- Geometry: XY plane at z=0; overall rectangle 300×200 mm. Two adjacent open faces: x∈[0,120], y∈[0,200] and x∈[120,300], y∈[0,200], with one real shared edge. No solid, hole, thickness volume or curved surface. Build two planar faces and share their topology before writing STEP; never infer a shared node merely from coincident coordinates.
- Analytic source area: 60,000 mm²; face areas 24,000 and 36,000 mm². Source normal is +Z. Physical output is first-order tri3 shell, two source face/part identities.
- Fixed proposed mesh settings: Gmsh 4.15.2, dimension 2, one thread, preserve topology, global size 2.2 mm. From its XAO, select the left face UUID in the GUI and set local size 1.2 mm. Both baseline and refined candidates must actually contain 20k–100k physical elements and meet the original q/time gates.
- Scale estimate only: regular-triangle area h²√3/4 predicts about 28.6k baseline and 55.7k refined elements before transition/boundary effects. These are **not observed counts or acceptance evidence**. An out-of-range actual result is a recorded failure, not a reason to weaken the range or silently tune sizes.
- Local-size evidence: left-face element count increases by more than 2× and median element-edge length is below 0.75× its baseline; these are the same comparison measures used by the existing small SDK test. Retain target/non-target distributions and transition behavior. All pre-existing geometry entity UUIDs remain stable across XAO regeneration.
- Native plan: explicit Mg/mm/s document units; elastic steel ρ=7.8e-9 Mg/mm³, E=210000 MPa, ν=0.3; shell thickness 1 mm. Independent analytic mass is 0.000468 Mg. Export SH3N plus real PART/material/shell property and the selected condition/case cards, with positive +Z orientation and no zero-area cells.

## Planned source C2: touching two-solid block

- Original STEP contains two separate solids with coincident faces but distinct initial topology: A=[0,30]×[0,30]×[0,20] mm; B=[30,80]×[0,30]×[0,20] mm. Use separately constructed box shapes in a compound, without pre-fragmenting the original input.
- Exact volumes: A 18,000 mm³, B 30,000 mm³, total 48,000 mm³. Shared/coincident interface is x=30, area 600 mm². No overlap, gap, sliver or curved face.
- Fixed proposed settings: dimension 3, global size 2.3 mm, one thread. Branch 1 imports the original STEP with `conformal`; branch 2 regenerates that conformal XAO with `preserve`, selecting A's persistent volume UUID and local size 1.6 mm; branch 3 imports the **original STEP again** with `independent`. At most these three candidate generations for this source are planned. Conformal XAO → independent should be explicitly rejected by the existing preflight if attempted; it is not a supported automatic split operation.
- Scale estimate only: regular-tetrahedron volume h³/(6√2) predicts about 33.5k baseline and 58.2k locally refined elements. Real Gmsh counts remain to be measured; all actual admitted candidates must remain 20k–100k and meet q_min≥0.1, positive volume and 120 seconds.
- Conformal oracle: interface nodes are the actual intersection of A/B volume connectivity sets; interface triangular faces occur in both volume boundary sets with opposite orientation; every interface node is shared, no duplicated coincident nodes and no partial/hanging facets. Source/part ownership and volume totals remain exact.
- Independent oracle: A/B node ID sets are disjoint even on x=30; both interface triangulations cover the same 600 mm² geometry without being silently merged. Different tessellations are allowed because independence does not imply matching subdivisions. This is an interface-topology test, not validation of an active contact law.
- Local oracle: A's cell count >2× baseline and median tetra edge length <0.75× baseline; retain B and interface statistics. Regeneration preserves volume/surface UUIDs and the actual shared interface in the conformal branch.
- Native plan: the same explicit steel and a supported solid property. Independent analytic mass is 0.0003744 Mg. Native TETRA4 count equals physical cell count, two PARTs and correct assignments; display boundary triangles must not be exported as extra physical shells. Native nodes must preserve the selected branch's shared/independent relation.
