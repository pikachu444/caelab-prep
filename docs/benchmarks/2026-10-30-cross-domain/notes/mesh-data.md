# 메시·표시 데이터의 보충 조사

이번 분야는 Gmsh·VTK·PyVista·MOAB·CGAL에서 공용 개발에 필요한 데이터/변환 계약을 조사했다. 새 메셔 알고리즘·DB·문서 모델을 설계하거나 라이브러리를 선정·설치하지 않았다. 정본은 [분야 근거](../domains/mesh-data.json)이며 ID가 기능 묶음과 원문 locator를 연결한다.

18개 원문 URL(문서·예제 16, 고정 tag 소스 2), 기술 예제 이미지 8개, 좁은 기능 묶음 10개를 확보했다. 이미지는 모두 model/quality 그림이고 UI 메뉴·대화상자 이미지는 0개다. 다른 분야 또는 기존 CAE 자료와의 URL 중복은 통합 시 따로 제거해야 한다. 원문 전체를 읽거나 오프라인 매뉴얼을 영구 보관했다는 뜻은 아니다.

| 필요한 질문 | 근거 묶음 | 개발에 주는 방향 |
|---|---|---|
| tag/handle/global ID/partition은 같은 번호인가 | P01 | 도구 내부의 식별 범위를 솔버 번호에 바로 대응시키지 않음 |
| node 수·차수·연결 순서가 DOF를 정의하나 | P02 | 기하 변환과 solver formulation 근거를 분리 |
| 메모리와 수명은 어디서 증가하나 | P03–04 | 배열 표현·보조 adjacency·공유/복사를 실제 버전에서 확인 |
| 화면에서 고른 face가 원본의 무엇인가 | P05 | 추출/분할 후 source 대응을 따로 검증 |
| 미지원 품질과 불량 셀을 구분하나 | P06–07 | family/metric/지원 상태와 threshold·문제집합을 별도 취급 |
| local sizing/fragment/최적화는 어떤 전제가 있나 | P08–09 | recipe·topology 변경·후처리의 근거를 이어 확인 |
| 파일/표시 dataset이 편집 문서를 대체하나 | P10 | 파일 표현과 사용자 모델의 권위를 구분 |

위 방향은 조사 결과에 대한 제안이며 제품 정책 확정이 아니다. 기존 문서/선택/jobs 담당과 연결할 질문은 ‘원본 변경 후 filter ID가 아직 유효한가’, ‘공유 배열을 변경하면 Undo 대상도 바뀌는가’, ‘worker가 만든 후보를 취소·폐기하면 표시와 문서의 소유자는 무엇을 유지하는가’다. 원 제품이 제공하지 않는 CAE 정책을 이 자료에 있는 기능처럼 채우지 않았다.

7개 필수 조사 묶음에는 모두 근거와 공백을 기록하고 반례 검색을 마쳤다. 이 한정 조사는 종료했지만 7개 모두 앱 적용 관점의 coverage는 partial이다. 런타임 재현은 0건이며 성능·Windows·고차/혼합 family 교환·solver 읽기·저장 재열기·조건 보존은 검증하지 않았다. API 존재나 예제 그림을 상용 메셔 또는 CAE 모델 편집 완성의 증거로 쓰지 않는다.

버전은 Gmsh 4.15.2, MOAB 5.6.0, CGAL 문서 표기 6.2.1, 다운로드한 PyVista 문서 표기 0.49.2다. VTK는 9.4.2 소스를 직접 읽고 9.6.1/9.7 문서는 각각 다른 근거로 유지했다. 특히 PyVista 검색 캐시의 0.49.1과 원문 0.49.2, CGAL의 latest redirect를 고정 실행환경으로 오인하지 않도록 기록했다.
