# 문서·참조 분야 조사 결과

2026-10-30. 이번 범위는 공식 사용자 조작과 기술 계약의 조사입니다. 제품 실행, 문서 모델 변경, DB 도입, GUI 구현은 수행하지 않았습니다.

## 확보한 것과 해석 범위

- 원문 URL 25개: FreeCAD 공식 문서 11개, FreeCAD 고정 소스/API 4개, OCCT 고정 API 7개, OCCT 안내서 2개, AutoCAD 공식 도움말 1개.
- 이미지 14개를 실제 다운로드하고 각각 시각 확인했습니다. 트리·대화상자 발췌 10개와 구조/의존성 그림 4개입니다. 최신 앱의 전체 화면 14개라는 뜻이 아닙니다.
- 좁은 기능 패턴 11개입니다. 각각 정상 조작·문서/API 위치·실패/Undo/저장 범위·CAE 이식 한계·미확인을 [document.json](../domains/document.json)에 연결했습니다.
- V/R은 0입니다. 읽은 문서/API는 실제 앱 재현이나 상용 동등성 증거가 아닙니다.

## 분야의 결론

다른 CAD의 문서 프레임워크에서 객체 정체성, 공유/복사, 변경 기록, 의존성 전파와 저장 책임을 학습할 수 있습니다. 같은 라이브러리를 채택해야 한다는 결론은 내리지 않았습니다. 기존 공용 모델 문서에 적힌 책임을 구체적인 API와 반례로 점검할 자료입니다.

| 기능 묶음 | 찾아볼 패턴 | 실제로 도움이 되는 질문 |
|---|---|---|
| 이름·ID·번호 | P01 | 표시 이름 변경과 삭제/재생성 뒤 참조는 어떻게 구별되는가? |
| 원형·배치·공유·복사 | P02·P03 | 같은 원본을 바라보는 변경과 독립 사본 편집을 사용자가 구분할 수 있는가? |
| 참조 삭제와 draft | P04 | 참조된 객체를 삭제하면 속성 편집의 미확정 값은 누구를 대상으로 남는가? |
| transaction·Undo·취소 | P05·P11 | 기록에 참여한 문서 변경과 작업 범위 밖 부작용은 어디까지 복원되는가? |
| 의존성·재계산·dirty | P06 | 저장 후 변경, 계산 필요, 계산 오류, 파생 결과 stale를 구분하는가? |
| 저장·외부 참조 | P07·P08 | API 성공 반환과 모든 자원·참조의 실제 파일 보존이 일치하는가? |
| topology 변경 | P09 | 불확실한 재연결을 확정하지 않고 진단·재선택할 수 있는가? |
| 대량 균질 자료 | P10 | 고수준 객체/관계와 수치 배열을 구분해야 하는 근거는 무엇인가? |

표의 P번호는 모두 document-P 접두사를 갖습니다. 예를 들어 P04는 document-P04입니다.

## 그대로 일반화하면 깨지는 지점

- FreeCAD의 문서 내 Name을 영원한 고유 키로 쓰면 삭제 후 이름 재사용을 놓칩니다(D01). solver native 번호의 namespace와도 다릅니다.
- 고정 FreeCAD 소스의 부분 로드 문서 save 분기는 실제 쓰기를 건너뛰면서 true를 반환합니다(D12). 성공 판정은 실제 효과를 봐야 합니다.
- OCAF transaction에 참여하려면 attribute의 변경 기록 계약이 필요하며, 문서를 걸친 동작은 같은 단일 transaction이라고 볼 수 없습니다(D23). UI draft, worker 중단, 파일 저장은 별도 경계입니다.
- AutoCAD의 참조 편집 Discard는 작업 집합 밖의 삭제를 복원하지 않습니다(D25). 상용 앱도 Cancel/Discard를 전역 복원으로 제공한다고 가정하면 안 됩니다.
- XDE는 교환용 의미이고 최종 앱의 FE component·재료·조건 의미를 제공하지 않습니다(D24).
- CAD naming과 shape instance가 있다는 이유로 재메시 FE 집합 복구, 절점 공유, formulation별 DOF를 해결했다고 주장하지 않습니다.
- TObj의 규모 주의는 특정 문서 구조의 특성입니다(D23). 이를 우리 앱 최대 요소 수나 현재 성능 결과로 쓰지 않습니다.

## 버전과 이미지의 한계

FreeCAD 공식 문서 저장소의 고정점은 0499378a238ce4c77c643b9cc4a03d0947381e45(2025-01-15), 읽은 앱 소스는 a6d3cb585abeca5643db060ea30d9cda09bb9857(2026-10-29)입니다. 문서 화면의 실제 빌드는 대부분 미확인입니다. Graphviz 결손 화면의 파일명은 FreeCAD0.17을 명시합니다. 이 문서와 현재 소스를 하나의 빌드에서 관찰한 연속 작업으로 묶지 않았습니다.

OCCT 소스는 53706f78a8640c4407bdcc6752df13a270b159f2(2026-10-20)에 고정했습니다. 요청한 과거7.9.0 안내서 URL이 현재8.0.1 표시 페이지로 이동하므로 실제 읽은 현재 URL만 자료 수에 포함했습니다. 웹 안내서와 고정 소스가 같은 배포 빌드라고 보장하지 않습니다.

S01–S09는 주로 오래된 트리/패널 발췌입니다. S10–S11은 의존성 그림, S12는 외부 프로그램 부재 대화상자, S13은 reference-key 개념도, S14는 XDE label 계층 그림입니다. 이들은 최신 GUI 외관 토큰·font/DPI·전체 docking 규칙의 근거가 아닙니다. 다운로드 원본은 assets/document에 있으며 제품에 편입할 아이콘/브랜드 자산이 아닙니다.

## 교차 담당에게 전달할 공백

선택 담당과는 삭제 중 property draft·선택 수명을, 입력 담당과는 mixed 값·붙여넣기 실패와 transaction을, jobs 담당과는 대상 변경/삭제/닫기 뒤 결과 채택을 교차 확인해야 합니다. 이번 원문에서 답을 찾지 못한 범위는 기존 제품의 보장 또는 우리 정책으로 위장하지 않았습니다.

특히 삭제·Undo 후 native 번호/객체 ID의 정확한 복원, 여러 문서 저장 실패, 디스크 부족·권한·한글 경로, 재계산 취소 후 이전 파생 결과 보존은 실제 입력과 빌드를 정한 후 별도 확인할 항목입니다. 자료 조사에서 이 항목이 남는다는 이유로 현재의 한정 조사 작업을 무한히 연장하지 않습니다.

## 이번 조사 종료 판정

사전에 고정한 여섯 기능 묶음 모두 사용자 목적/조작, 관련 API·소스·예제 위치, 예외와 공백, 이식 가능한 책임과 금지 일반화를 기록했습니다. 대량 자료 경계를 추가했습니다. 다른 접근과 명시 반례를 검색하고 남은 공백의 영향을 기록했으므로 이번 분야 수집은 종료합니다. 이 판정은 구현 착수 준비나 제품 기능 완료를 뜻하지 않습니다.

원문 전체 HTML/소스는 tmp/document의 분석용 임시 자료이고 최종 배포물에 넣지 않습니다. JSON과 이 노트는 독자 요약이며 긴 원문/코드 인용을 포함하지 않습니다.
