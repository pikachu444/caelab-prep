# 긴 작업·취소·산출물 수명 — 직접 조사

root가 Qt 6.8.9, Python 3.11.18, QGIS 3.40 문서/API, VS Code rolling 문서/API, Win32 문서를 읽어 비교했다. 분야의 14개 URL과 10개 패턴은 `domains/jobs.json`에 있다. 실제 프로그램·SDK·Windows 프로세스는 실행하지 않았다.

## 필요한 방향

진행 표시, 취소 요청, backend 종료 확인, 임시 결과 폐기, 문서 변경 되돌리기, 최종 파일 교체를 각각 구분해야 한다. 이는 이번에 검토한 API들의 차이에서 얻은 설계 참고점이며 새로운 공용 job 시스템의 구현 결정은 아니다. Prep과 Workbench의 현재 작업 소유권도 변경하지 않는다.

- `jobs-P01–03`: 진행/취소 UI와 계산의 협조적 중단. basic run과 promise mode를 구분한다.
- `jobs-P04–06`: 시작·종료·로그, Windows 중단·자식 프로세스, timeout·파이프의 차이.
- `jobs-P07–08`: 단일 파일의 안전한 교체와 여러 산출물/문서 채택, 실행 도중 입력·수명 변경의 공백.
- `jobs-P09–10`: host 작업 소유권, GUI/script 진입, watch의 busy/done과 프로세스 종료의 차이.

API 이름이 같아도 OS·라이브러리마다 의미가 다르므로, 후속 개발자는 `jobs-P05`의 원문 위치를 먼저 대조해야 한다. 동일하게 cancel 버튼이 있다고 backend가 정지하거나 기존 모델로 복구되는 것은 아니다. 문서의 보호 조건을 끄는 옵션도 있으므로 정상 예제만으로 저장 실패 정책을 결정하면 안 된다.

## 종료 판정

필수 일곱 묶음에 원문/API 위치와 반례를 연결했다. 단일 파일과 문서의 통합 채택, 입력 개정에 따른 stale 결과, 현 host의 실제 연결은 부분 근거다. 이 공백은 다른 문서의 기능을 이어 붙여 채우지 않았다. 좁은 API 계약의 `supported`는 전체 사용자 작업·성능·CAE 의미의 완료 판정이 아니다.

후속 구현에서 필요한 확인은 선택한 backend의 취소 가능성, 실제 Windows launcher/자식 관리, 문서 닫기와 늦은 완료 통지, 산출물 검증·채택 실패다. 이번 조사에서 이들을 구현하거나 재현하지 않았다.

## 확보/접근 기록

QGIS 사용자·개발 문서는 web open으로 관련 절을 읽었으나 직접 HTTP 다운로드는 403이었다. API 문서는 읽을 수 있었다. Qt Fusion 진행 대화상자는 실제 이미지로 확인했으며 외관 평가가 아닌 진행/취소 표시의 정적 근거다. vendor 프로그램·문서 전문은 배포물에 넣지 않는다.
