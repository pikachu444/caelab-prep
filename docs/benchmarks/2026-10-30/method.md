# 수집 방법과 판정

## 역할을 정하기 전의 합의

root와 두 독립 참여자가 조사 방법부터 토론했다. 한 명은 Astra, 다른 한 명은 별도 검토자다. 제품 수나 그림 수를 늘리는 방식 대신, 선행 상태와 결과를 추적하는 시나리오 단위를 채택했다. 제품군별 담당은 버전과 문맥을 유지하고, 두 검토자는 공통 과업으로 누락을 찾는다. 이후에만 수집 역할을 확정했다.

핵심 비교축은 트리/속성, 선택, 메시 흐름, 조건/케이스, 검증/저장이다. Abaqus·COMSOL·HyperMesh·NFX·MeshFree를 심층으로, Naksha·BeidPrep을 공개 자료의 한계까지 조사했다. 추가 제품은 구체적인 미충족 비교축이 생길 때만 검토한다.

## 증거 종류와 세 가지 판정

| 필드 | 의미 | 증거로 대신할 수 없는 것 |
|---|---|---|
| S | 실제 확인한 정적 화면/대화상자/메뉴/그림 | 버튼을 누른 뒤의 결과 |
| D | 원문에 명시된 절차·입력·제약 | 이번 직접 실행 |
| V | 실제 관찰한 연속 영상과 시각 | 그 영상에 없는 실패/저장 |
| R | 동일 입력에서 직접 실행한 앱의 관찰 | 이번에 없는 라이선스/환경 확인 |
| `design_path_grounded` | 좁은 정상 장면의 메뉴·선택·필수 입력·결과가 문헌으로 연결됨 | 과업 전체 준비/실행 검증 |
| `full_workflow_ready` | 정한 과업의 필수 오류·취소·저장 등까지 연결됨 | 상용 제품 전체 동등성 |
| `reproduction_verified` | 실제 앱과 같은 입력으로 재현 검증함 | 다른 형상/버전의 일반화 |

`status=grounded`는 첫 축의 좁은 장면을 뜻한다. fixture 미보유만으로 문헌상의 정상 경로를 없던 것으로 만들지는 않는다. 반대로 정상 경로 1개로 전체 과업을 완료 처리하지 않는다. 제품마다 장면의 분량이 달라 grounded 개수를 제품 품질 순위로 사용하지 않는다.

이번 자료의 마지막 두 축은 모두 false다. 관측하지 않은 상태는 unavailable/partial/unknown으로 남긴다. 아직 실패를 보지 않았다는 이유로 성공을 추정하지 않는다. 번호가 있는 정적 before/after 그림과 실제 연속 조작은 구분한다.

## 출처와 원본

- 제목·버전·접근일·원문 URL, PDF 실제 페이지 번호/0기준 인덱스/인쇄 쪽수, 이미지 URL/발췌 좌표를 연결한다.
- Abaqus 2025판 자료는 Virginia Tech 미러 호스팅이다. vendor-origin 내용과 벤더 직접 호스팅을 구별한다.
- PDF 렌더 치수·배율을 앱 원래 DPI/글꼴/행 높이로 바꾸어 쓰지 않는다.
- 파일 해시는 실제 보유 발췌 파일에만 기록한다. hash/내부 ID를 제품 GUI의 주 정보로 노출하는 요구가 아니다.
- 벤더 원본 매뉴얼 전체를 공개 저장소에 재게시하지 않는다. 출처 표시는 재배포 허가와 다르며, 화면 발췌는 분석용 참고다.
- 벤더 로고/아이콘을 자체 제품 리소스로 편입하지 않는다. 공용 자산은 별도의 배포 가능한 원본으로 작성한다.

## 교차감사에서 바로잡은 사항

BeidPrep 하단 선택 띠 APPLY를 카드 폼의 확정 버튼으로 오인하지 않게 수정했다. 열린 Editing 패널 내부 경로와 전역 메뉴 진입을 분리했다. HyperMesh의 서로 다른 tet 생성 경로를 연속 절차로 합치지 않았고, UI 없는 모델 crop 5개를 UI 수에서 제외했다. MIDAS 문서 발췌의 렌더 해상도와 앱 DPI를 분리했다. Abaqus의 누락된 Assembly 단계와 COMSOL의 별도 예제 연결/취소 결손을 남겼다.

## 이 수집 묶음의 종료 조건

7제품의 T01–T09마다 확보/부분/자료부재의 이유가 기록되고, 장면의 source/asset 참조와 실재 파일/치수가 맞으며, 두 검토자가 근거를 넘는 주장을 지적해 수정하면 수집을 닫는다. 이 조건은 완전한 제품 복제 준비의 종료 조건이 아니다. 미충족 기능을 성공으로 세지 않으며, 같은 자료를 반복 다운로드하거나 새 제품을 계속 추가하지 않는다.
