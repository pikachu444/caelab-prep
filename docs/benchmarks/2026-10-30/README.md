# CAE GUI 벤치마크 근거 자료

2026-10-30. **참조 자료 수집과 설계 명세 보강**이다. 제품 GUI·메셔를 구현하거나 아래 상용 앱을 이번에 직접 실행한 결과가 아니다. 기존 엔진 우선이라는 개발 방향을 유지한다.

## 범위와 실제 확보물

7제품, 9과업을 조사했다. 원문 URL·문서판/화면 빌드·페이지/그림·메뉴·입력·선행 상태·결과·오류/취소·저장의 연결은 `products/*.json`에 보관한다. 이미지 원본을 공개 저장소에 일괄 복제하지 않고, 원문 이미지 URL 또는 PDF 페이지와 발췌 좌표로 추적한다. 별도 전달한 오프라인 자료집은 색인에 연결된 화면 발췌를 포함한다. 벤더 PDF 전문·프로그램·아이콘 라이브러리는 포함하지 않는다.

## 조사 전 토론과 역할

root·Astra·독립 검토자가 먼저 제안과 반론을 교환했다. 제품 사진 대신 **과업 × 시작 상태 × 조작 × 결과 상태**를 조사 단위로 정했다. 제품별 수집과 기능별 교차검토를 함께 수행하며, NFX와 MeshFree를 한 제품으로 합치지 않기로 했다.

4수집 담당은 Abaqus / COMSOL / HyperMesh / NFX·MeshFree를 맡았다. root는 Naksha·BeidPrep 원문/화면과 타 제품의 핵심 장면을 직접 확인하고 통합했다. Astra는 동작·상태의 연결을, 별도 검토자는 출처·버전·화면 분류를 감사했다. 최종 해석은 [방법과 판정](method.md)을 따른다.

## 과업과 사용법

T01 작업공간/가져오기, T02 트리/속성, T03 선택/가시성, T04 메시 설정/생성, T05 재료/조건/케이스, T06 품질/오류/취소, T07 저장/내보내기/재열기, T08 실행/자동화, T09 표/곡선/단위다.

1. 해당 제품 JSON에서 과업과 장면을 찾는다. 같은 제품 안에서도 다른 예제/버전의 장면을 이어붙이지 않는다.
2. `source_ids`의 문서와 `asset_ids`의 이미지/PDF locator를 확인한다. `file`은 별도 자료집 내부 경로다.
3. 메뉴·선택·입력값·결과의 관측 범위를 읽고 `unknowns`를 구현자가 임의로 채우지 않는다.
4. [공용 자산 요구](common-assets.md)의 자체 설계 선택과 원 제품의 관측 사실을 구분한다.
5. [실행 작업서](../../execution-stages.md)의 해당 단계에서 지원 범위·자체 입력·목표 화면·환경을 고정한 뒤 구현한다.

## 아직 충족하지 않은 것

- 동일 입력의 직접 실행 재현은 이번에 0건이다. S/D 자료를 R로 보고하지 않는다.
- 123장면의 일부 좁은 정상 경로는 문헌으로 연결되지만, 모든 과업의 실패/취소/저장·재열기까지 완결된 것은 아니다.
- Beam 파트에서 Assembly 인스턴스로 이어지는 자료가 끊긴 곳, meshing control 대화상자/저장창이 없는 곳, 다른 예제의 그림이 수록된 곳을 그대로 표시했다.
- Naksha·BeidPrep 공개 자료는 상세 UI가 있어도 입력 fixture·메뉴 진입·연속 동작을 충분히 제공하지 않는다. 두 제품을 완전 복제할 자료가 확보됐다고 하지 않는다.
- 화면의 정확한 글꼴·배율·모든 hover/focus/disabled 상태·도킹 제약은 전부 확보되지 않았다. 대표 그림을 근거로 자동 추정하지 않는다.
- 이 자료집은 상용 제품 전체의 기능/커널 동등성을 입증하지 않는다. 복잡 자동 중립면·범용 all-hex 연구를 확정 개발로 되돌리지 않는다.

이번 수집 묶음은 출처·자산·장면의 추적과 감사 보완으로 종료한다. 남은 항목은 해당 구현 장면의 필요에 따라 좁혀 확인한다. 자료가 모였다는 이유로 P0의 실제 입력·환경·최종 목표 화면 결정을 완료 처리하지 않는다.
