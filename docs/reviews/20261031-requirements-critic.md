## Six corrections: requirement to actual result

1. **Shared active object and qualified picks.** `application/contracts.py` defines `SelectionProvider`; RAD and neutral providers expose select/active-object, and both windows consume approved state. Presentation changes during an old draft are deferred and then consumed after Apply/Revert, including clear selection. `session.py` maps an existing native PART to displayed elements and real read-only properties. That one existing relation satisfies the agreed scope; additional material/condition relations were not required. Candidate picks are rejected by document ID, fresh session epoch, document revision, projection revision and resource state token. Persistent ObjectRefs remain distinct from transient renderer candidates. Source and tests cover same saved IDs after reopen, stale clear-picks, ambiguous IDs, all approved VTK refs and token refresh after scalar changes without geometry rebuilding. Native picking subsequently produced canonical selection and visible orange highlighting.

2. **Actual shared actions and lifecycle.** `ui/actions.py` owns unique action IDs, capability/context enablement, checked state and shared QAction instances; both windows register actual commands. `ui/shell.py` supplies the common draft/replace/close coordinator and shared file task, consumed by both hosts. RAD injects its MeshViewport into the common ViewportFrame; the neutral workspace uses that frame around its table/plot. RAD automatic Apply and neutral explicit Apply remain host policies. Merely defining unused helpers would not satisfy this requirement; the actual call sites do.

3. **Consumed tokens and semantic icons.** `ui/design/tokens.py` supplies real QSS, icon rendering and widget/plot metrics. `appearance.py` supplies the missing original section/load/contact/set/select/result/job assets; `rad_provider.py` maps native categories to those meanings. Original icon families are represented without enabling unavailable modelling commands. The catalogue is not the sole consumer of a disconnected token table.

4. **Typed reference editing.** Neutral material properties expose existing curve ObjectRefs in the shared reference combo. PropertyEditor submits the typed value through SetProperties; the provider validates document/resource/kind/object identity before committing. Undo/Redo and codec v2 persistence preserve the relationship; v1 remains readable. Tests exercise the actual Gallery picker and reject wrong-document/resource/kind, missing curve and raw-string candidates atomically. Associated-curve display follows the committed reference. Native input selected the load curve and verified Apply/save/reopen. This is a typed application reference, not an invented constitutive law or new RAD creation flow.

5. **Browsable catalogue and distinct composition.** `ui/catalogue.py` exposes 33 assets with key, purpose, source, actual consumer scenes, implementation status, provenance and known permission. Permission text does not invent a repository redistribution licence. Numeric/vector/units/properties/tree/curve/action/message scenes use real common controls; value scenes submit commands. The material/curve composition is labelled separately. Standalone narrow curve and metadata defects were corrected. More importantly, native integrated 960×640 review found fields and Apply/Revert outside the narrow dock with no recovery. The final outer QScrollArea makes that workspace scrollable. At DPR 1/1.5/2, actual native scroll/focus checks established full target bounds and QTest Revert/edit/Apply/Undo succeeded. Inspected narrow images show accessible fields and complete buttons; content outside the current nonzero scroll offset is recoverable. A responsive redesign or all page/state combinations was not required.

6. **RAD close semantics.** The common coordinator asks Save/Discard/Cancel before validating. Discard bypasses invalid drafts; Cancel preserves them; Save validates and waits for real asynchronous completion. The `choosing` guard suppresses scalar editingFinished while the real modal question owns focus. Draft capture/restore preserves values after failed/cancelled Save. I challenged patched-dialog tests because they could miss focus-triggered commits; actual offscreen-modal coverage and native QTest button events now cover that path.
